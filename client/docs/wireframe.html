Server replies the app handles

ReplyWhenWhat the app does
200 / 201 stateAny accepted requestRedraws from state.step
409 stale_stepThe answer or feedback is for a step the session has already leftRedraws from the state in the reply; no error shown
404 session_not_foundThe server restarted and lost the sessionReturns to 1 with "Your session ended on the server. Please start again."
400, 5xxRejected or failed requestBanner "The server could not handle that request." with Try again
no replyServer down or unreachableBanner as in the last frame, with Try again

Rules the frames follow

  • Question text, answer labels and guess text are the server's strings, shown unchanged. The answer buttons are built from step.options, so the app draws however many the server sends.
  • Food and cafeteria names stay in Korean; everything the app or engine authors is English.
  • "Question N of up to M" uses max_questions (10 by default). After M answers the engine must guess. With no cap, the line reads "Question N" and the bar is hidden.
  • Start over in the header is available in every session state and never asks the server.
